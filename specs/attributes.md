# Attributes

This document specifies the attributes each entity type carries. The metamodel defines the types and how they relate. An attribute not recorded here is not part of the model.

## 1. Conventions

### 1.1 Identifier

Every entity carries an identifier, generated by the software and stored in the file beside the attributes. It stands first on the first tab of every type, as each table shows.

### 1.2 Values

Every attribute is optional and every value is stored as text. An unset attribute is an absent key. An unset Applicable means not yet assessed. A computed attribute is never stored.

### 1.3 Kinds

Each attribute uses one of the kinds below.

| Kind | Meaning |
|---|---|
| identifier | The entity type's code and a running number, generated by the software, never changed or reused. |
| text | A single line of text. |
| multiline | Text of any length, line breaks preserved. |
| choice | One value from the Values column. |
| set | Any number of the values in the Values column, stored as chosen, separated by semicolons in the column's order. |
| hyperlink | A web address. |
| number | A whole number within the bounds the Values column gives. |
| date | A calendar date, stored as its year, month and day, 2026-09-24. |
| drawing | SVG text, shown only as an image, accepted only after the drawing check the requirements state. |
| table | Rows of columns. The columns are the rows beneath whose key is the table's key, a dot and their own, each a text, a multiline, a date, a choice or a number. Stored as one line per row, cells parted by tabs and quoted as CSV where needed, empty rows dropped. |
| computed | Derived from the parameters beside it by the method the Values column names. Shown, never stored. |
| rating | A risk estimation by the method the project has chosen. Its parameters are the method's in chapter 7, each stored under the row's key as a prefix to the parameter's, and with no method it is a text stored under the prefix and Rating. |
| level | A required integrity level in the terms of the standard chosen by the attribute the Values column names. Its options and key per standard stand in chapter 8, and with no standard it is a text under the last key. |
| rationale | Why the class of the parameter the Values column names was chosen. |
| entities | The identifiers of the entities related by the relationship type the Values column names first, as they stood when the group it names second last changed. Written by the software, separated by semicolons in ascending order. |

Computed and rationale are used by the parameters of chapter 7 alone.

### 1.4 Tabs

A type's attributes shall stand in one table, in the editor's order, the Tab column naming the tab each row stands on. The first tab holds the type's own attributes and is named by the last word of the type's name. Every type shall end with a Diagram tab and a Notes tab. Keys shall be unique within a type. Tab names are stored in no file.

### 1.5 Template

Each entity type shall be written using the template below. A sentence or two may stand under the type's heading where the table cannot say it.

```markdown
### 3.1 Entity Type (CODE)

| Tab | Attribute | Kind | Values | Help | Key |
|---|---|---|---|---|---|
| Type | Identifier | identifier |  | Assigned by the tool from the entity type's code and a running number, never changed and never reused. | id |
| Type | Name | kind | value; value | What it is, in one or two sentences. | key |
| Tab name | Name | kind | value; value | What it is, in one or two sentences. | key |
| Diagram | Diagram | drawing |  | A diagram of it, made in draw.io and shown as an image. | drawing |
| Notes | Notes | multiline |  | Anything worth keeping that no field holds, such as how something was assessed. | notes |
```
