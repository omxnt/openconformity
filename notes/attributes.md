# Attributes

This document specifies the attributes each entity type carries, what the file holds for each and what a value means. The metamodel defines the types and how they relate, and this document defines what data each one holds. An attribute not recorded here is not part of the model.

## 1. Conventions

### 1.1 Identifier

Each entity carries an identifier, generated by the software and never changed or reused. It is not an attribute. A file carries it beside the attributes, and the editor shows it read-only as the first cell of the type's own tab.

### 1.2 Values

Every attribute is optional, and every value is stored as text. An unset attribute is the absence of its key, and clearing a value removes the key. A computed attribute is never stored. It is derived from the attributes beside it wherever it is shown.

### 1.3 Kinds

Each attribute uses one of the kinds below.

| Kind | Meaning |
|---|---|
| text | A single line of text. |
| multiline | Text of any length, line breaks preserved. |
| choice | One value from the Values column. |
| set | Any number of the values in the Values column, stored as those chosen separated by semicolons, in the order the column lists them. |
| hyperlink | A web address. |
| number | A whole number, kept between the least and the greatest the Values column gives. |
| date | A calendar date, stored as its year, month and day, 2026-09-24. |
| drawing | A picture held as SVG text, shown only as an image and accepted only after the drawing check the requirements state. |
| table | Rows of columns. The columns are the rows beneath it whose key is the table's key, a dot and their own, each a text, a multiline, a date, a choice or a number. Stored as one line per row with the cells parted by tabs, a cell holding a tab, a break or a quotation mark quoted as a CSV cell is, and a row with every cell empty dropped. |
| computed | A value derived from the parameters beside it by the method the Values column names. Shown, never stored. |
| rationale | Free text for why the class of the parameter the Values column names was chosen. |
| entities | The identifiers of the entities related by the relationship type the Values column names first, as they stood when the group it names second last changed. Written by the software, stored separated by semicolons in ascending order. |

### 1.4 Tabs and groups

A type's attributes stand on tabs, each a `####` heading under the type, numbered, in the order the editor shows them. The first tab holds the type's own attributes and is named by the last word of the type's name. Every type ends with a Notes tab. A tab may hold groups, each a `#####` heading and a table within the tab. A type's keys are unique across all of its tables, and tab and group names are stored in no file.

A group's heading may carry tags.

| Tag | Meaning |
|---|---|
| `when key = value` | The group is shown only while the attribute of that key holds that value, and what it holds is kept only then. A save made while the group is hidden clears what it held, after a question naming it. The key may name an attribute of the project where the type has none of that key. |
| `when key =` | The same, holding while the attribute is unset. |
| `after key` | A group waiting on a choice stands after that attribute instead of after the one it waits on. |

Groups sharing a name and waiting on the same attribute are one slot, and one of them holds at a time. A group closing on a computed attribute is a rating, whose parameters are chosen together in a dialog.

### 1.5 Template

Each entity type is written as below. One or two sentences may stand under the type's heading where the tables cannot say it. A parameter of a rating carries no help of its own, since the rating's dialog shows its classes.

```
### 3.1 Entity Type (CODE)

#### 3.1.1 Type

| Attribute | Kind | Values | Help | Key |
|---|---|---|---|---|
| Name | kind | value; value | What it is, in one or two sentences. | key |

#### 3.1.2 Tab name

| Attribute | Kind | Values | Help | Key |
|---|---|---|---|---|
| Name | kind | value; value | What it is, in one or two sentences. | key |

##### Group name `when key = value`

| Attribute | Kind | Values | Help | Key |
|---|---|---|---|---|
| Name | kind | value; value | | key |

#### 3.1.3 Notes

| Attribute | Kind | Values | Help | Key |
|---|---|---|---|---|
| Notes | multiline | | Anything worth keeping that no field holds, such as how something was assessed. | notes |
```

### 1.6 Labels

An entity is labelled by its reference and its title with a space between, or by its title alone where the type carries no reference. An entity whose Applicable is No or whose Eliminated is Yes stays in the model and is shown greyed, as out of play.

### 1.7 Help

The help a name carries where it names a rating or a slot rather than an attribute, and the identifier's, is recorded once below.

| Name | Help |
|---|---|
| Identifier | Assigned by the tool from the entity type's code and a running number, never changed and never reused. |
| Initial risk estimation | The risk before protective measures, estimated by the method chosen or typed where none is. |
| Residual risk estimation | The risk with the protective measures in place, estimated by the method chosen or typed where none is. |
| Required integrity level | The level the safety function must reach, in its standard's own terms. |

## 6. Risk estimation

An accident scenario is rated by one of the three methods ISO/TR 14121-2:2012 [1] gives as its examples, chosen on the project, or by no method, the ratings then typed. Each method's parameters are attributes of the scenario, and the level, index or score they come to is read from the tables below wherever it is shown and never stored. Every parameter carries its source's classes alone. The class definitions behind them are the source document's own, at the clause given, and are not reproduced here.

### 6.1 Risk matrix

ISO/TR 14121-2:2012, 6.2.2, Table 1. The severity across, the probability down.

| Probability | Catastrophic | Serious | Moderate | Minor |
|---|---|---|---|---|
| Very likely | High | High | High | Medium |
| Likely | High | High | Medium | Low |
| Unlikely | Medium | Medium | Low | Negligible |
| Remote | Low | Low | Negligible | Negligible |

### 6.2 Risk graph

ISO/TR 14121-2:2012, 6.3.2, Figures 3 and 4. Severity S and exposure F down, occurrence O and avoidance A across, giving a risk index from 1 to 6, shown with the band the second table gives it.

| S F | O1 A1 | O1 A2 | O2 A1 | O2 A2 | O3 A1 | O3 A2 |
|---|---|---|---|---|---|---|
| S1 F1 | 1 | 1 | 1 | 1 | 2 | 2 |
| S1 F2 | 1 | 1 | 1 | 1 | 2 | 2 |
| S2 F1 | 2 | 2 | 2 | 3 | 3 | 4 |
| S2 F2 | 3 | 4 | 4 | 5 | 5 | 6 |

| Risk index | Risk |
|---|---|
| 1; 2 | lowest |
| 3; 4 | medium |
| 5; 6 | highest |

### 6.3 Numerical scoring

ISO/TR 14121-2:2012, 6.4.2. The severity score SS and the probability score PS, each a whole number from 0 to 100, add up to the risk score RS, shown with the category the third table gives it. The first two tables say which class a score falls in.

| Severity score | Class |
|---|---|
| 100 | catastrophic |
| 90 – 99 | serious |
| 30 – 89 | moderate |
| 0 – 29 | minor |

| Probability score | Class |
|---|---|
| 100 | very likely |
| 70 – 99 | likely |
| 30 – 69 | unlikely |
| 0 – 29 | remote |

| From | To | Category |
|---|---|---|
| 160 | 200 | high |
| 120 | 159 | medium |
| 90 | 119 | low |
| 0 | 89 | negligible |
