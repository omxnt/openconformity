# Release review

This review checks openconformity at commit `b23c0fa` of 27 September 2026, before the release of v1.0.0-beta.1. It ran the software and its tests, read the code and the documents, and probed the safeguards that protect what the software writes. Two reviewers read the code and the documents independently, and every finding they made was checked against the code or reproduced before it entered this record. It closes with a verdict and the fixes it asks for before the release.

## 1. Method

| Pass | What it covered | How |
|---|---|---|
| Execution | The test suite, the browser drives, the page's policy and headers, the shipped data, secrets, versions and licences | `./run.sh`, the headless Chrome drives, and shell checks of the tree and its history |
| Code | Every file under `app/` | A reviewer reading for bugs, dead code, stale comments, layer breaks, security patterns and interface text |
| Documents | README, CLAUDE.md, SECURITY.md, `specs/`, `docs/`, the site's text and both `security.txt` files | A reviewer checking links, cross-references, claims against the code, stale statements and the writing rules |
| Probes | The drawing check, against diagrams saved beside a specification | Hostile drawings passed through the check, then opened on their own in Chrome with a local server logging every request they made |

## 4. What was found clean

- **Sinks and parsing.** No module builds markup from text, evaluates text, fetches or opens a socket. Text reaches the page through `textContent` and `setAttribute` alone, and the one parser of foreign data is `JSON.parse` behind the validator.
- **The frame.** draw.io runs sandboxed on its own origin with no referrer. A message is heard only from its frame and origin, within the size limit and naming a known event, and a returned drawing is decoded by the software's own decoder and checked.
- **The exporters.** The workbook escapes the markup characters, removes what XML forbids and writes every cell as text, so no formula runs. The Markdown escapes its own syntax. Zip entry names come from identifiers the file format restricts, so no path can leave its folder.
- **The model and storage.** The children index is dropped on every change to filing, history shares no object with the live model, the validator checks counters, cycles, depth and ownership, and a stale write never overtakes a newer one.
- **Layers.** No runtime import points up a layer, and there is no cycle.
- **Documents.** Every relative link and every line anchor resolves. The 96 requirements are all in verification with their counts right. Every identifier the security model and the decision log cite exists, and every document in `docs/` has the template's form.

## 5. Verdict

The software is close, and the release should wait for one round of fixes. Finding 1 is the one that matters for users. A diagram a user saves and opens can report to an outside address, which the security model believed impossible. Findings 2 and 3 are behaviour a user can meet in ordinary use, and 4 is a promised shortcut that does not exist. The documents findings, 5, 6 and 10 to 12, correct statements that are untrue today.

| Round | Findings | Kind |
|---|---|---|
| Code, before release | 1, 2, 3, 4, with 7, 8 and 9 recommended | One commit, each with a test, finding 1 proven against the probes in Chrome |
| Documents, before release | 5, 6, 10, 11, 12, with 13 recommended | One commit, the decision that the beta is open among them |
| After the beta | 14 to 26 | As the beta's feedback allows |

The release gates from the security model stand after these rounds. Once the gate is down, read the headers, read Cloudflare's settings for injected scripts, confirm two-factor login on both accounts, pass the test run and a clean console on the merged commit, and fetch both `security.txt` files from the live hosts.
