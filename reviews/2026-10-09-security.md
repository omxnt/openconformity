# Security 2026-10-09

A third-party security review of openconformity, made against commit `a915c5a` of 7 October 2026 on main, release v1.0.0-beta.3. Every module under `app/` was read. The test suite was run under Node with a shim for the JavaScriptCore globals. The drawing check, the Markdown writer and the link rule were driven with hostile inputs. The live headers of `app.openconformity.org` were read through an external scanner. The repository's settings, the branch rules and the host's settings could not be read from this review. The maintainer states that every account carries a second factor, which is taken on that statement.

## 1. Verdict

The software is secure for its purpose, which is holding confidential design and risk-assessment data on the user's own device. Nothing found runs code, reads the project or leaves the device. No finding is High. The concept carries most of the security, no server, no accounts, no dependencies and no network but one consented frame, and the code does not squander it. Against a cloud product with accounts, the design is stronger on custody, since there is no data to breach, and weaker on governance, since there is no identity, audit trail or recovery. Both follow from the same choice, and the choice is the right one for this data.

## 2. What holds

| Area | What was checked |
|---|---|
| Rendering | No markup sink in any module. Text reaches the page by `textContent` and attributes by fixed names. The policy requires trusted types, so the browser enforces it. |
| Network | `connect-src 'none'` live. No fetch, beacon or socket in the code. |
| Dependencies | None. No package, lockfile or build step. |
| The project file | Parsed as data, gated in order, refused whole on any error. Prototype keys refused. |
| Drawings | The strict XML parser and the check refused every bypass tried. CSS escapes, entity-encoded and whitespace-split `javascript:`, `@font-face src`, `srcset`, `base`, `meta refresh`, SMIL on `href` and `style`, `feImage`, `textPath`, `cursor`, `mask`, HTML inside `foreignObject` and namespaced `script` were all caught. Shown only as an image. |
| The editor | One frame, fixed origin, sandboxed, messages filtered by source, origin, size, shape and event. The returned drawing passes the same check. |
| Exports | Workbook cells as inline strings only. Markdown escapes what a renderer would autolink or structure. Drawings are checked again before they enter a zip. |
| Headers | The live headers match `app/_headers`. Full policy in the header, opener policy, no referrer, transport security, permissions policy. The findings of the review of 6 October are fixed, but for C-06. |
| Secrets | None in the repository. |

## 3. Findings

| Id | Finding | Feasibility | Impact | Risk |
|---|---|---|---|---|
| R-01 | The editor's model inside a drawing is not checked. The root `content` attribute is exempt from the resource rule, so a file can carry `image=http://...` in a cell style. Nothing loads on open or render. When the user consents and edits that drawing, the editor loads the image, and Apply embeds the result. What leaks is an address and the fact that the drawing was opened, the same class as SC-19. Refuse a model that names a remote image on load, or record it as a residue of SC-08. | Medium | Low | Low |
| R-02 | The path to main is unverified, as C-06 of the last review found. No workflow runs the suite, commits are unsigned, and the host deploys main within minutes. A required check that runs `tests/run.sh` and a rule on main that needs it, with signed commits, are the cheapest controls. They add nothing to the software. With every account under a second factor, this is the one gap left between trustworthy software and a trustworthy service. | Low | High | Medium |
| R-03 | The host sends `access-control-allow-origin: *` by default. Harmless for public static files. `Cross-Origin-Resource-Policy: same-origin` in `_headers` closes it, as C-07 proposed. | Low | Low | Low |
| R-04 | The parser can be tightened at no cost. Refuse a document type declaration with an external identifier, refuse a name with two colons, and add `handler` to the forbidden elements. None is exploitable in a current browser. | Low | Low | Low |
| R-05 | The site's headers could not be confirmed. The scanner returned the app's headers for `openconformity.org`, so whether `site/_headers` is served stands unverified. | | | |

## 4. On the concept

The philosophy of holding no user data by design is sound and is the reason the software is secure. The boundary the maintainer owns is the code the user runs, what leaves and enters the device through it, what it writes to disk, the honesty of the promise, and the channel by which the code reaches the user. The first four are held well. The fifth is R-02. The trade-offs, no recovery, no collaboration without the user arranging it, no view of use, are the ones draw.io accepted under the same philosophy, and that model has held for over a decade. The software goes further than its inspiration in one respect, shipping no third-party code at all.

## 5. Not verified

Branch protection, whether private vulnerability reporting is enabled, the host's settings, the second factor on the accounts, and the site's served headers.
