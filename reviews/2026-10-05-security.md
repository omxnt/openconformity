# Security 2026-10-05

This document is a security review of openconformity, made against commit `13fe327` of 4 October 2026, the release v1.0.0-beta.2, by probing the software's controls with inputs the audit of 27 September did not try. Nothing in the repository was changed by it.

No way was found for a project file, a drawing or the draw.io frame to run code in the software or to send data off the device. The page's policy, the headers the host serves and the parsers all held as `docs/security.md` says. Seven weaknesses were verified, two of them medium: a cubic replay that lets a 0.6 MB file freeze the tab for 40 seconds, and counters the validator accepts that make the software write files it then refuses. The rest are low or informational.

## Findings

Each finding was reproduced against commit `13fe327` of 4 October 2026 by importing the real modules in Node 22. Severity follows the scale in `docs/security.md` section 1.2.

| No. | Severity | Where | What |
| --- | --- | --- | --- |
| 1 | Medium | `files.js:182`, `model.js:454` to `475` | Composition replay is cubic. A valid 578 KB file of 4,000 chained entities takes 38 s to open and freezes the tab. |
| 2 | Medium | `validator.js:209`, `model.js:220` to `227` | Counters of `1e21` or `2^53` pass validation. The next entity gets an id the software refuses on reopening, or silently overwrites an existing entity. |
| 3 | Low | `drawing.js:277` | A link's `href` may be `data:image/svg+xml`, a document that can run script. Chrome refuses the navigation today, so the risk is latent. |
| 4 | Low | `markdown.js:64`, `:73`, `:95`, `:106` to `:108` | A bare carriage return, and line breaks in titles and headings, inject Markdown structure. Bare `https://` and `www.` become links in GFM. |
| 5 | Low | `drawing.js:263` | `xlink:onload` and other prefixed handlers pass the handler check, which reads the full name rather than the local name. Chrome does not fire them. |
| 6 | Low | `xlsx.js:131` to `133`, `views.js:84` | A cell of 130,000 lines throws on Excel save. A section name of 100,000 spaces takes 13 s to slug. |
| 7 | Info | `drawing.js:279`, `drawing.js:83`, `risk.js:166`, `xlsx.js:52` | The `content` exemption is global rather than on the root. `&#0;` and lone surrogates pass the parser. A probability of `__proto__` renders an empty outcome tag. Sheet names keep line breaks. |

### 1. A cubic replay freezes the tab on a file under 1 MB

`buildModel` calls `relate` once per relationship. For each call `ownerOf` scans every relationship and `wouldOwnItself` walks the whole owner chain, calling `ownerOf` at each step. A chain of n entities linked by `req-decomposes-into-req` costs O(n³).

Measured on `poc6-chain.mjs`: 1,000 entities (142 KB) 0.6 s, 2,000 (287 KB) 4.7 s, 4,000 (578 KB) 37.8 s. The validator alone takes 45 ms. At 8,000 entities (1.2 MB) the estimate is 5 minutes. The same code runs on restore from IndexedDB, so a tab that opened such a file reopens into the same freeze until the stored project is cleared. SC-04 accepts a freeze only for files of hundreds of megabytes.

Fix: keep an owner index on the model (`Map<target, source>`) so `ownerOf` is O(1), or let `buildModel` skip the composition cycle check the validator already made.

### 2. The validator accepts counters that break the id invariant

`validator.js:209` checks `Number.isInteger(value) && value >= 1`. `1e21`, `1e300` and `2^53` are integers to JavaScript. `addEntity` builds the id from `String(counter)` and never checks whether that id is already in `nodes`.

Reproduced on `poc1-counters.mjs` and `poc1b-store.mjs`. With `counters.LEG = 1e21` the next entity is `LEG-1e+21`. Saving and reopening is refused, and through the store the autosaved project fails restoration and the user lands on the landing page with the project set aside. With `counters.HAZ = 2^53` two successive `addEntity` calls both succeed with the id `HAZ-9007199254740992`, `nodes.size` grows by one, and the first entity's attributes are lost. This contradicts CT-03, which says the software never writes a file it refuses.

Fix: `Number.isSafeInteger` in the validator and in `restoreCounters`, an upper bound, and a refusal in `addEntity` and `addFolder` when the issued id already exists.

### 3. A link in a drawing may point at a script-capable data document

`drawing.js:273` refuses `data:` targets that are not `data:image/`, and `:277` exempts an `a` element's `href` from the local-or-data rule. So `<a href="data:image/svg+xml,...">` with an `onload` inside the payload passes `checkDrawing`. Clicked in Chromium, the navigation is blocked, since browsers refuse top-level `data:` navigation. A viewer that allows it would run the script. Any `http` or `https` link is also accepted and, clicked in a standalone `.svg`, navigates the viewer to that address, which SC-19 describes as only a request that reports the file was opened.

Fix: refuse every `data:` scheme on `a href`. Say in SC-19 that a link in a saved diagram navigates on click.

### 4. The Markdown export lets a value open a heading, a list or a link

`markdownCell` turns `\r?\n` into `<br>` but a lone `\r` passes. `paragraphs` splits on `\r?\n` only. The title, subtitle, headings and captions pass through `markdownText`, which never touches line breaks. CommonMark treats a bare carriage return as a line ending, and GitHub's renderer makes a bare `https://` or `www.` address a link.

Reproduced on `poc3-markdown.mjs`: a cell `ok\r# Injected heading\r- item` is emitted as written, an entity title `ELM-001 Title\n# Injected` becomes a new heading, and a cell `see https://evil.example/track?u=1` becomes a link in GitHub. TH-50 and CT-36 name exactly this threat.

Fix: normalise `\r\n?` to `\n` before everything, run `proseLine` on every line of headings, subtitles and captions or replace their line breaks with spaces, and escape the colon after `http`, `https` and `www`.

### 5. Prefixed handler attributes pass the drawing check

`drawing.js:263` tests `key.startsWith('on')` on the full attribute name, while every other check in `walk` uses `local(key)`. `xlink:onload`, `ev:onload` and `foo:onclick` pass. Verified in Chromium, none of them fires. Fix: `local(key).startsWith('on')`.

### 6. Two save paths fail or stall on large values

`xlsx.js:131` spreads every line of every row of a column into `Math.max`. One cell of 200,000 lines (400 KB) throws `RangeError`, and `saveExcel` at `views.js:373` has no catch, so the click does nothing. `views.js:84` runs `/\s*\(\d+\)$/` over a section name. A title of 100,000 spaces followed by `(1x` takes 12.9 s. Fix: a loop for the maximum, and a pattern that does not backtrack over whitespace.

### 7. Informational

`drawing.js:279` skips the CSS scan for any attribute whose local name is `content`, on every element, while only the root carries draw.io's model. `drawing.js:83` accepts `&#0;` and `&#xD800;`, which a browser refuses as not well-formed, so the check says ok for a file that does not render. `risk.js:166` looks up `MATRIX[value]` with the file's value, so a probability of `__proto__` or `toString` returns `undefined` rather than `null` and an empty outcome tag renders. `xlsx.js:52` keeps line breaks in sheet names and allows the reserved name `History`.

Outside the software's scope as `docs/security.md` draws it, the project site at `openconformity.org` carries an inline theme script and no content security policy, and the host serves `/_headers` and every unknown path as the application page rather than a 404.

## The live hosts

The headers of `app.openconformity.org` match `app/_headers` and the page's policy matches `index.html`, read on 5 October 2026. The page loads two scripts, `theme.js` as a classic script and `modules/app.js` as a module, and no inline script. Every request during load went to the host alone. A `fetch` from the page's own console fails, as `connect-src 'none'` requires.

| Header | Value |
| --- | --- |
| `content-security-policy` | `frame-ancestors 'none'` |
| `strict-transport-security` | `max-age=15552000; includeSubDomains` |
| `x-content-type-options` | `nosniff` |
| `referrer-policy` | `strict-origin-when-cross-origin` (Cloudflare's default) |
| `access-control-allow-origin` | `*` (Cloudflare Pages' default, harmless for static files) |
| `nel`, `report-to` | Cloudflare's network error logging, with `success_fraction` 0 |
| `permissions-policy` | Not set |
| `cross-origin-opener-policy` | Not set |

Two additions would cost nothing. `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), display-capture=()` in `_headers` denies the device to the page itself, as `FRAME_ALLOW` already denies it to the frame. `Cross-Origin-Opener-Policy: same-origin` cuts the window reference a page that opened the software could keep. The HSTS `max-age` of 180 days could go to a year with `preload` once the maintainer is sure the site stays HTTPS.

The project site at `openconformity.org` is out of the model's scope. It carries no policy and one inline script, so adding a policy means moving that script to a file as the application did. The site's `security.txt` is in place and expires 27 September 2027.

## Method and evidence

The review was made against commit `13fe327` of 4 October 2026 on `main`, cloned from GitHub on 5 October 2026. It follows the model in `docs/security.md` and the audit of 27 September in `reviews/`, and asks of each control whether it holds under inputs the earlier audit did not try.

What was read: every module under `app/`, `index.html`, `theme.js`, `_headers`, `site/index.html`, `docs/security.md`, `reviews/2026-09-27-security.md`, `SECURITY.md`, both `security.txt` files, `.claude/settings.json` and the tests for drawings, files, validator, store and editor.

What was run: the test suite under Node 22. Eight probe scripts importing the real modules, for counters, prototype keys, Markdown, Excel, hyperlinks, the composition chain, the rating matrix and the section-name pattern. Forty or so candidate drawings put to `checkDrawing`, and the accepted ones opened as standalone files in Chromium 1194 with a logging server on `127.0.0.1` to see whether any request left. The live page loaded in a browser with its network log and console read, and its headers read through securityheaders.com since the shell here cannot reach the host.

What was not done: nothing was changed in the repository, no request was made to the host beyond page loads, and nothing was sent to draw.io. The host's settings, branch protection and the private reporting switch are the maintainer's to read.

The probe scripts can be handed over as fixtures for `tests/` on request.
